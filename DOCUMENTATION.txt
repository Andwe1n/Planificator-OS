## 2. FUNDAMENTE TEORETICE

### 2.1 Heap-ul Binar

Un heap binar este un arbore binar complet care satisface proprietatea heap:
- **Max-heap**: Părintele ≥ fiii
- **Min-heap**: Părintele ≤ fiii

#### Reprezentare ca Array

Pentru un nod la index i:
- Părinte: (i - 1) / 2
- Fiu stâng: 2 * i + 1
- Fiu drept: 2 * i + 2

Exemplu:
```
      50
     /  \
   30    40
  /  \  /
 10  20 35

Array: [50, 30, 40, 10, 20, 35]
Index:  0   1   2   3   4   5
```

#### Complexități Temporale

| Operație | Complexitate | Explicație |
|----------|--------------|------------|
| Insert (push) | O(log n) | Heapify-up până la root |
| Extract (pop) | O(log n) | Heapify-down până la frunze |
| Peek (top) | O(1) | Primul element din array |
| Build heap | O(n) | Bottom-up heapify |
| Search | O(n) | Traversare completă necesară |

#### Algoritmul Heapify-Up (pentru Insert)

```
1. Adaugă elementul la sfârșitul array-ului
2. Compară cu părintele
3. Dacă proprietatea heap e încălcată:
   - Schimbă cu părintele
   - Repetă de la pas 2
4. Altfel: STOP
```

#### Algoritmul Heapify-Down (pentru Extract)

```
1. Înlocuiește root-ul cu ultimul element
2. Șterge ultimul element
3. Compară cu fiii
4. Dacă proprietatea heap e încălcată:
   - Schimbă cu fiul mai mare (max-heap) / mai mic (min-heap)
   - Repetă de la pas 3
5. Altfel: STOP
```

### 2.2 D-ary Heap

Generalizare a heap-ului binar cu D copii per nod.

#### Formule pentru Index

Pentru un nod la index i și D copii:
- Părinte: ⌊(i - 1) / D⌋
- Al k-lea copil (k ∈ [0, D-1]): D * i + k + 1

#### Avantaje și Dezavantaje

| D | Avantaje | Dezavantaje |
|---|----------|-------------|
| 2 (Binary) | Echilibrat, simplu | Standard |
| 3-4 | Mai puține nivele, cache-friendly | Mai multe comparații la pop |
| 8-16 | Foarte rapid la insert | Pop foarte lent |

#### Alegerea Valorii D

- D = 2: Folosit în majoritatea cazurilor
- D = 3-4: Optim pentru workload-uri mixte
- D mare: Pentru operații predominantly insert

### 2.3 Fibonacci Heap (Concept Avansat)

Deși nu e implementat în versiunea de bază, Fibonacci heap oferă:
- Decrease-key: O(1) amortizat
- Insert: O(1)
- Extract-min: O(log n) amortizat
- Union: O(1)

Utilizat în algoritmul Dijkstra optimizat.

### 3.2 Design Patterns Utilizate

#### 3.2.1 Template Method Pattern

```cpp
template<typename T, typename Compare>
class HeapBase {
    // Definește interfața comună
    virtual void push(const T& value) = 0;
    virtual T pop() = 0;
};
```

Clase derivate implementează detaliile specifice.

#### 3.2.2 Strategy Pattern

Comparatorul este parametrizabil:
```cpp
MaxHeap<int> = BinaryHeap<int, std::less<int>>;
MinHeap<int> = BinaryHeap<int, std::greater<int>>;
```

#### 3.2.3 RAII (Resource Acquisition Is Initialization)

Toate resursele sunt gestionate automat prin destructori.

### 3.3 Principii de Design

✓ **Single Responsibility**: Fiecare clasă are un scop clar
✓ **Open/Closed**: Extensibil fără modificare
✓ **Liskov Substitution**: Heap-urile derivate sunt interschimbabile
✓ **Dependency Inversion**: Programare la interfețe, nu implementări
✓ **DRY** (Don't Repeat Yourself): Cod reutilizabil

## 4. IMPLEMENTĂRI DETALIATE

### 4.1 HeapBase - Interfața Abstractă

```cpp
template<typename T, typename Compare = std::less<T>>
class HeapBase {
protected:
    std::vector<T> data;          // Stocarea datelor
    Compare comp;                 // Comparatorul
    size_t comparison_count;      // Statistici
    size_t swap_count;
    
public:
    virtual void push(const T& value) = 0;
    virtual T pop() = 0;
    virtual const T& top() const;
    
    bool empty() const;
    size_t size() const;
    void clear();
    
    // Statistici pentru analiza performanței
    size_t get_comparisons() const;
    size_t get_swaps() const;
};
```

**Rolul Clasei:**
- Definește interfața comună pentru toate heap-urile
- Gestionează statistici de performanță
- Oferă implementări implicite pentru operații simple

### 4.2 BinaryHeap - Implementarea Clasică

```cpp
template<typename T, typename Compare = std::less<T>>
class BinaryHeap : public HeapBase<T, Compare> {
    
    void push(const T& value) override {
        data.push_back(value);
        heapify_up(data.size() - 1);
    }
    
    T pop() override {
        T result = data[0];
        data[0] = data.back();
        data.pop_back();
        heapify_down(0);
        return result;
    }
    
private:
    void heapify_up(size_t index);
    void heapify_down(size_t index);
};
```

**Caracteristici:**
- Implementare standard O(log n) pentru insert/delete
- Optimizare build_heap în O(n)
- Funcție update() pentru actualizarea priorităților

### 4.3 DaryHeap - Generalizarea cu D Copii

```cpp
template<typename T, size_t D = 4, typename Compare = std::less<T>>
class DaryHeap : public HeapBase<T, Compare> {
    static_assert(D >= 2, "D must be at least 2");
    
    // Similar cu BinaryHeap dar cu D copii
    // Formula: k-th child = D * i + k + 1
};
```

**Avantaje:**
- Arbore mai "lățit" → mai puține nivele
- Mai bună localitate în cache pentru operații insert
- Configurabil pentru diferite workload-uri

**Dezavantaje:**
- Mai multe comparații la extragere
- Complexitate mai mare la implementare

## 5. APLICAȚIE PRACTICĂ - OS SCHEDULER

### 5.1 Process Control Block (PCB)

```cpp
struct Process {
    int pid;                  // Process ID
    int priority;             // Prioritate curentă
    int base_priority;        // Prioritate originală
    int burst_time;           // Timp CPU necesar
    int remaining_time;       // Timp rămas
    int arrival_time;         // Moment sosire
    ProcessState state;       // NEW, READY, RUNNING, WAITING, TERMINATED
    
    // Statistici
    int waiting_time;
    int turnaround_time;
    int response_time;
};
```

### 5.2 Arhitectura Scheduler-ului

```
┌─────────────┐
│   NEW       │
│  Processes  │
└──────┬──────┘
       │
       ↓ arrival_time
┌──────────────────┐
│   READY QUEUE    │ ← Max-Heap (priority)
│  (Max Heap)      │
└────────┬─────────┘
         │
         ↓ Scheduler Decision
    ┌────────┐
    │ RUNNING│
    └───┬────┘
        │
    ┌───┴───┐
    │   I/O?│
    └───┬───┘
   Yes  │  No
        │
    ┌───┴────────┐
    │ WAITING    │
    │ (Min Heap) │
    └────────────┘
```

### 5.3 Algoritmi de Scheduling

#### 5.3.1 Priority Scheduling cu Preempție

```
Pentru fiecare time quantum:
1. Verifică procese noi (arrival_time <= current_time)
   → Adaugă în ready_queue
   
2. Verifică I/O completion
   → Mută procese din waiting → ready
   
3. Aplică aging (previne starvation)
   FOR each process in ready_queue:
      IF age >= aging_threshold:
         priority += priority_boost
         age = 0
         
4. Selectează procesul cu prioritate maximă
   process = ready_queue.pop()
   
5. Execută pentru time_quantum
   process.execute(time_quantum)
   
6. Dacă nu e terminat:
   - Dacă necesită I/O → waiting_queue
   - Altfel → ready_queue
```

#### 5.3.2 Priority Aging Mechanism

**Problema Starvation:**
Procese cu prioritate mică nu sunt niciodată executate.

**Soluția:**
```cpp
void apply_aging() {
    for (auto& proc : processes) {
        if (proc.state == READY) {
            proc.age++;
            if (proc.age >= aging_threshold) {
                proc.priority += priority_boost;
                proc.age = 0;
            }
        }
    }
}
```

### 5.4 Metrici de Performanță

#### Waiting Time
Timpul total petrecut în ready queue.
```
waiting_time = (start_time - arrival_time) + (în_așteptare între quantum-uri)
```

#### Turnaround Time
Timpul total de la arrival la completion.
```
turnaround_time = finish_time - arrival_time
```

#### Response Time
Timpul de la arrival la prima execuție.
```
response_time = start_time - arrival_time
```

#### CPU Utilization
Procentul de timp când CPU-ul lucrează.
```
cpu_utilization = (total_cpu_time / total_time) * 100
```
